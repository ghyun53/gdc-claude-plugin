## 요청 내용

GitHub 연동 안내서(`site/github.html`, https://seonmikii.github.io/gdc-claude-plugin/github.html) **맨 첫 부분**에 블록을 넣고, 아래 내용을 안내한다. 이미 본문에 있는 내용이라도 여기서는 더 자세히 쓴다.

1. 깃허브 사용 시 **개인 연동** 필요
2. **프로젝트별 깃허브 레포지토리 연동** 필요
3. 기존 프로젝트일 경우 **프로젝트별 깃허브 사용자 연동(매핑)** 필요. 새 프로젝트는 불필요

진행 중 추가 지시:

- 캡처 4장을 사용자가 새로 찍은 주석 캡처(1 개인 연동 / 2 레포지토리 추가 / 3 라벨·사용자 매핑 / 4 기존 프로젝트의 전체 가져오기+매핑 설정)로 **교체**하고 내용도 그에 맞춘다.
- 머리말 꼬리표 「주의 · 시작 전 필수」 → **「빠른 안내서」**.
- 제목 「GitHub을 쓰기 전에 이 세 가지를 먼저 연동하세요」 → **「GitHub을 프로젝트에 연동하려면 이 순서를 꼭 지켜주세요」**.
- **순서를 지키지 않았을 경우**는 4번 캡처(기존 프로젝트 — 전체 가져오기 → 매핑 설정)로 안내한다.
- 페이지 **전체**의 문장이 길고 장황하니 불렛포인트·명사형으로 간략히 정리하고, `—`는 `-`로 바꾼다.
- 빠른 안내서 세부 수정: 머리말 리드 2개(masthead 리드·언어 안내) 삭제, 빠른 안내서 리드는 「① … → ② …」만 남김, ①의 "연결 전/후" 줄 → "해제" 안내로 교체, ①②의 캡션(왜 필요한가·권한) 삭제, ②는 1)~4) 번호 단계로 교체, 두 번째 묶음 제목 → 「이미 진행중인 프로젝트에 Github 연동하기」, 그 리드·캡션 삭제 후 2단계로 축약.
- 「자세히 보기」(00장) 이후 전 구간을 사용자 문체로 재작성.
- 1·2를 한 순서로 묶어 끊고, 그 아래를 **「위 순서와 다르게 프로젝트를 이미 생성했다면 아래 순서대로 해주세요」** 라는 별도 제목의 묶음으로 분리한다.

## 배경

안내서는 01 워크스페이스 → 02 프로젝트 레포 → 03 내 계정 → 04 태스크 사용 순서로 되어 있어, **"쓰기 전에 각자/프로젝트마다 무엇을 어떤 순서로 해둬야 하는가"** 가 한 화면에 모여 있지 않았다. 고객 안내 메일로 같은 내용을 반복 설명하게 되어 매뉴얼 맨 앞으로 끌어올린다.

## 수행 계획

1. 캡처 4장 마스킹 — 기존 안내서 규칙(실명·이메일·GitHub 아이디·웹훅 URL 흐림)에 맞춰 가우시안 블러 후 webp 변환, 본문에 base64로 인라인(기존 13장과 같은 방식).
2. `site/github.html` 「한눈에 보기」 위에 `.must` 블록 신설 — 번호 1·2·3 항목마다 설명 + 실제 화면, 각 항목에서 본문 해당 장으로 가는 링크.
3. 한/영 문구(`data-en`) 동기화, 목차 맨 위에 항목 추가.
4. 검증 — 이미지 로드, 목차 앵커, 한/영 전환, 좁은 화면·다크 모드 렌더링.

- [x] `.must` 블록 신설 — 「빠른 안내서」 + 「GitHub을 프로젝트에 연동하려면 이 순서를 꼭 지켜주세요」 아래 3개 항목

## 참고 사항

- 변경 파일: `site/github.html` 1개. 기존 01~06장 본문은 고치지 않고 맨 앞에 요약만 추가했다(중복은 의도된 것 — 요청이 "이미 있으면 더 자세하게").
- MCP 도구·서버 동작과 무관한 문서 페이지 수정이라 로컬 사전 검증(WS3) 대상이 아니다. `plugin.json` 버전도 그대로 둔다.
- 캡처는 사용자가 운영 화면(제머나이소프트 WS6 「GDC 테스트」 프로젝트, `gemiso-dev/gdc-test`)에서 직접 찍은 주석(빨간 네모·번호·화살표) 포함본을 그대로 썼다. 기존 13장은 1440px 폭, 이번 4장은 약 1210px 폭이다.
- 새 프로젝트에 3번이 불필요한 이유는 레포 추가 직후 매핑 설정 창이 바로 열려 그 자리에서 저장하기 때문(본문 2-1 3단계와 같은 근거).
- 1차 캡처(다른 프로젝트 화면 4장)는 사용자 요청으로 폐기하고 2차 캡처로 전부 교체했다.
