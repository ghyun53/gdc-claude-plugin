GDC GITHUB

GitHub 연동 안내서

GDC 워크스페이스에 GitHub을 연결하고 프로젝트에 레포를 붙이면, GitHub 이슈와 GDC 태스크가 함께 움직입니다. 워크스페이스 → 프로젝트 → 내 계정 → 태스크 순서로 진행합니다.

GDC 화면은 한국어와 영어를 모두 지원합니다. 이 안내서의 버튼 이름은 선택한 언어의 화면 표기를 따릅니다.

00

한눈에 보기

단계마다 누가, 어디서 하는지 정리했습니다. 1·2단계는 워크스페이스·프로젝트마다 한 번, 3단계는 사람마다 한 번 합니다.

단계 위치 권한
1 워크스페이스에 GitHub 연결 워크스페이스 설정 → 기타 → GitHub 설치 연결 워크스페이스 소유자·관리자
2 프로젝트에 레포 연결 프로젝트 → 연동 → GitHub 레포 연동 프로젝트 관리자 (새 레포를 고를 때는 워크스페이스 소유자·관리자 권한도 필요)
3 내 GitHub 계정 연결 설정 → 연동 → GitHub 계정 연결 모든 사용자
4 이슈 발행·PR 연결 태스크 상세 → GitHub 영역 프로젝트 편집 권한이 있는 사용자 (뷰어 제외)

어떤 레포를 연결할 수 있나요? GDC GitHub 앱이 설치되어 있고 앱에 접근이 허용된 레포만 연결할 수 있습니다. 현재는 제머나이소프트(gemiso-dev) 조직이 대상입니다. 앱을 '선택한 레포'로 설치했다면 그 레포만 보입니다.

01

워크스페이스에 GitHub 연결

GDC 앱이 설치된 GitHub 계정·조직을 워크스페이스에 연결합니다. 워크스페이스 소유자·관리자에게만 보이는 화면입니다.

1 워크스페이스에 GitHub 연결 · 1-1 설치 연결하기

설치 연결하기

GitHub에 한 번 로그인해 승인하면, 내 계정이 볼 수 있는 설치가 워크스페이스에 연결됩니다.

  1. 1

    사이드바에서 워크스페이스 설정을 열고 기타 탭으로 이동합니다.

  2. 2

    GitHub 설치 연결 카드에서 설치 연결을 누릅니다. 이미 연결된 설치가 있으면 설치 추가를 누릅니다.

  3. 3

    GitHub 화면에서 승인합니다. 기타 탭으로 돌아와 「GitHub 설치를 연결했습니다.」가 보이면 완료입니다.

  4. 4

    앱이 아직 설치되지 않았다면 「연결할 수 있는 GitHub 설치가 없습니다.」가 나옵니다. GitHub에서 앱 설치를 눌러 설치합니다. 조직에 설치하려면 그 조직의 Owner 권한이 필요합니다.

이 승인으로 내 GitHub 계정 연결(3단계)도 함께 이루어집니다. 다른 GitHub 계정으로 승인하면 GDC에 연결된 계정이 그 계정으로 바뀌며, 카드에 안내가 표시됩니다.

1 워크스페이스에 GitHub 연결 · 1-2 설치 관리

설치 관리

카드에는 설치마다 계정·상태·레포 범위와 연결된 레포·가져온 이슈 수가 표시됩니다.

  1. 1

    설치 해제는 이 설치를 쓰는 워크스페이스의 모든 프로젝트 연동을 끝냅니다. 레포 연결과 이슈 연결은 보관되며, 다시 연결을 누르면 그대로 복원됩니다.

  2. 2

    GitHub에서 앱도 제거하기를 함께 선택하면 GDC의 레포 접근 권한이 완전히 회수됩니다. 다시 쓰려면 앱을 새로 설치해야 하며 조직 관리자 권한이 필요합니다.

  3. 3

    설치 하나는 워크스페이스 하나에만 연결할 수 있습니다. 다른 워크스페이스로 옮기려면 기존 워크스페이스에서 먼저 해제합니다.

02

프로젝트에 레포 연결

프로젝트의 연동 탭에서 레포를 연결합니다. 이슈 관리·WBS 프로젝트 모두 지원합니다. 프로젝트 하나에 레포를 여러 개 연결할 수 있지만, 레포 하나는 프로젝트 하나에만 연결됩니다.

2 프로젝트에 레포 연결 · 2-1 레포 추가

레포 추가

워크스페이스에 연결된 설치에서 레포를 고릅니다.

  1. 1

    프로젝트에서 연동 탭을 열고 GitHub 레포 연동 영역을 찾습니다.

  2. 2

    레포 추가를 누르고 레포를 고른 뒤 다음을 누릅니다. 이미 연결된 레포는 「연결됨」으로 표시되어 고를 수 없습니다.

  3. 3

    이어서 매핑 설정 창(2-2)이 열립니다. 매핑을 저장하면 연결이 완료됩니다.

레포 목록은 워크스페이스 소유자·관리자 권한이 있어야 보입니다. 권한이 없는 프로젝트 관리자에게는 「레포를 찾을 수 없습니다.」로 나오므로 워크스페이스 관리자에게 연결을 요청합니다. 새 프로젝트를 만들 때 「GitHub 레포 연동」을 선택해 대표 레포 하나를 바로 연결할 수도 있습니다.

2 프로젝트에 레포 연결 · 2-2 매핑 설정

매핑 설정

레포의 사용자·라벨·상태를 GDC 항목과 연결합니다. 기본값이 채워져 있으니 확인 후 저장합니다.

항목 내용 · 기본값
사용자 레포 이슈에 등장한 작성자·담당자입니다. GitHub 계정을 연결한 사람(3단계)은 자동으로 매칭되고, 나머지는 '미매핑'이 기본값입니다. 프로젝트 멤버가 아니면 작성자에만 매핑됩니다.
라벨 라벨마다 태그·유형·우선순위·매핑 안 함 중 하나로 지정합니다. type:…·priority:… 라벨은 프로젝트에 같은 값이 있으면 유형·우선순위로, 나머지는 태그로 지정됩니다. 없는 유형·우선순위는 이 창에서 바로 만들 수 있습니다.
상태 열린 이슈와 닫힌 이슈를 각각 어떤 GDC 상태로 둘지 정합니다. 열림은 예정 계열, 닫힘은 완료 계열 상태가 기본값입니다.
미매핑 담당자 매칭되지 않은 담당자를 봇 계정에 귀속(기본값)할지 비워둠으로 둘지 정합니다. 매칭되지 않은 작성자는 항상 봇 계정으로 들어갑니다.

프로젝트에 다른 레포가 있으면 사용자·상태 매핑을 다른 레포에도 적용하는 옵션이 나타납니다(라벨은 제외). 이 창을 열면 매칭된 워크스페이스 멤버가 프로젝트 멤버로 추가됩니다.

2 프로젝트에 레포 연결 · 2-3 기존 이슈 가져오기

기존 이슈 가져오기

매핑을 저장하면 레포에 이미 있는 이슈를 어떻게 할지 묻는 창이 열립니다.

  1. 1

    전부 가져오기(기본값) — 이슈 전체를 태스크로 만듭니다. 이슈가 많으면 시간이 걸리며, 진행 상황은 레포 줄에 표시됩니다.

  2. 2

    기존 이슈는 가져오지 않기 — 연동 이후 새로 열리거나 수정되는 이슈만 들어옵니다. 나중에 전체 가져오기로 언제든 전부 가져올 수 있습니다.

  3. 3

    나중에 결정 — 정할 때까지 레포 줄에 범위 정하기 버튼이 남습니다.

이후 GitHub의 변경은 실시간으로 반영되며, 레포 줄에 「실시간」 배지가 표시됩니다. GitHub의 하위 이슈는 GDC 하위 태스크로 들어옵니다.

2 프로젝트에 레포 연결 · 2-4 연결 관리

연결 관리

연결된 레포 줄에서 다음 작업을 할 수 있습니다.

작업 설명
변경분 가져오기 마지막 가져오기 이후 바뀐 내용을 가져옵니다.
전체 가져오기 (⋯ 메뉴) 레포 전체를 처음부터 다시 가져오며, 이미 가져온 이슈도 다시 동기화합니다. 매핑을 바꿨거나 GitHub 계정을 새로 연결한 사람이 있을 때 사용합니다.
매핑 설정 2-2의 매핑 설정을 다시 엽니다.
동기화 일시중지 / 재개 멈춘 동안 GitHub의 변경이 들어오지 않고 GDC의 변경도 GitHub에 반영되지 않습니다. 이미 가져온 태스크는 그대로이며, 재개하면 그동안 GitHub에서 바뀐 내용을 다시 가져옵니다.
연동 해제 연동을 끝냅니다. 가져온 태스크와 연결된 PR은 그대로 남으며, 가져온 태스크도 휴지통으로 보내기를 선택하면 함께 휴지통으로 갑니다. 해제한 레포는 「해제된 연결」에 남아, 다시 연결하면 그동안 바뀐 내용까지 가져오고 완전히 정리하면 가져온 태스크를 휴지통으로 보내고 레포를 다른 프로젝트에 연결할 수 있게 됩니다.
03

내 GitHub 계정 연결

어떤 GitHub 계정이 나인지 GDC에 알려 두면, 이슈를 가져오거나 발행할 때 작성자·담당자로 인식됩니다. 사람마다 한 번 해 둡니다.

3 내 GitHub 계정 연결

설정에서 연결

GitHub에 로그인해 한 번 승인하면 됩니다.

  1. 1

    프로필 메뉴에서 설정을 열고 연동 탭으로 이동합니다.

  2. 2

    GitHub 계정 연결 카드에서 GitHub 계정 연결 버튼을 누르고 GitHub에서 승인합니다.

  3. 3

    GDC로 돌아오면 카드에 연결된 계정(@아이디)이 표시됩니다. 끊으려면 연결 해제를 누릅니다. 이미 가져온 태스크는 그대로 남습니다.

계정을 연결하기 전에 가져온 태스크는 프로젝트 관리자가 전체 가져오기(2-4)를 실행해야 작성자·담당자가 바뀝니다. 매칭은 워크스페이스·프로젝트 멤버만 대상이며, 담당자로 매칭되려면 프로젝트 멤버여야 합니다.

04

태스크에서 사용하기

레포가 연결되면 태스크 상세 패널 맨 위에 GitHub 영역이 생겨, 이 태스크의 이슈와 PR이 표시됩니다.

4 태스크에서 사용하기 · 4-1 동기화 방향

동기화 방향

GitHub → GDC는 항상 반영되고, GDC → GitHub는 이슈마다 켜고 끕니다.

방향 반영되는 내용
GitHub → GDC 이슈 제목·본문·열림/닫힘·담당자·라벨·댓글이 실시간으로 반영됩니다. GitHub에서 이슈를 삭제하면 태스크는 삭제되지 않고 숨김(보관) 처리됩니다.
GDC → GitHub 제목·설명·상태(열림/닫힘으로)·담당자·유형·우선순위·댓글이 반영됩니다. 단, 이슈 줄의 GDC 변경을 GitHub에 반영 스위치가 켜져 있을 때만입니다. 일정·진행률은 반영되지 않습니다.

스위치의 기본값이 다릅니다. GitHub에서 가져온 이슈는 꺼진 상태로, GDC에서 발행한 이슈는 켜진 상태로 시작합니다. GDC에서 고친 내용이 GitHub에 보이지 않으면 이 스위치부터 확인합니다.

4 태스크에서 사용하기 · 4-2 GitHub 이슈로 발행

GitHub 이슈로 발행

GDC 태스크를 GitHub 이슈로 만듭니다. 태스크 하나에 이슈 하나만 연결됩니다.

  1. 1

    태스크의 GitHub 영역에서 이슈 발행을 누릅니다.

  2. 2

    레포를 고릅니다(하나뿐이면 자동 선택). 한 번만 옮기고 끝낼 것이 아니라면 발행 후에도 GDC 변경을 GitHub에 계속 반영합니다를 켜 둡니다.

  3. 3

    발행을 누릅니다. 잠시 후 이슈가 만들어지며, 이슈 맨 위에 GDC 태스크 링크가 붙습니다.

태스크를 만들 때 「GitHub 이슈로 발행」을 선택해 바로 발행할 수도 있습니다. 본문의 이미지·첨부는 GitHub으로 옮길 수 없어 GDC 링크로 대체됩니다. 라벨은 레포에 같은 라벨이 있을 때만, 담당자는 GitHub 계정을 연결했고 레포 권한이 있을 때만 반영됩니다.

4 태스크에서 사용하기 · 4-3 PR 연결

PR 연결

태스크에 PR을 직접 연결합니다. 여러 개를 연결할 수 있습니다.

  1. 1

    태스크의 GitHub 영역에서 PR 연결을 누릅니다.

  2. 2

    최근 PR 목록에서 고르거나, 「목록에 없나요? 번호를 직접 입력하세요.」에 PR 번호를 넣고 연결합니다.

  3. 3

    연결된 PR은 상태(open·draft·merged·closed)와 함께 표시됩니다. 해제하려면 PR 줄에 마우스를 올리고 연결 해제를 누릅니다.

PR 상태는 태스크 상태를 바꾸지 않습니다. PR이 병합되어도 태스크가 완료되지 않으니 상태는 직접 바꿉니다.

4 태스크에서 사용하기 · 4-4 PR 자동 연결

PR 자동 연결

PR 제목이나 본문에 태스크를 적어 두면 자동으로 연결됩니다. 브랜치 이름은 보지 않습니다.

적는 방법 예시
GDC 태스크 링크 (키워드 불필요) https://gdc.gemiso.com/…/tasks/1234
키워드 + 이슈 참조 (같은 줄) 관련 이슈: #15 · Fixes #12, #13 · closes owner/repo#7

키워드: closes·fixes·resolves(과거형 등 포함), 관련 이슈·연관 이슈·관련 태스크·관련 작업. 참조한 이슈가 같은 프로젝트의 태스크와 이미 연결되어 있어야 합니다. 코드 블록·인용문 안의 글은 무시합니다.

자동 연결을 풀려면 GDC가 아니라 PR을 고칩니다. PR 본문에서 링크·참조를 지우면 연결도 풀립니다. GDC에서만 해제하면 PR이 수정될 때 다시 연결됩니다.

05

자주 묻는 문제

막혔을 때 먼저 확인할 것들입니다.

레포 목록이 비어 있는 경우 (「레포를 찾을 수 없습니다.」)

새 레포를 고르려면 프로젝트 관리자라도 워크스페이스 소유자·관리자 권한이 필요합니다. 워크스페이스 관리자에게 연결을 요청합니다.

관리자인데도 없다면 GitHub 앱에 그 레포 접근이 허용되지 않은 것입니다. GitHub에서 앱의 레포 접근 범위를 확인합니다.

「'…' 프로젝트와 연동된 레포입니다.」가 나오는 경우

레포 하나는 프로젝트 하나에만 연결됩니다. 기존 프로젝트에서 연동 해제 후 완전히 정리(2-4)를 먼저 합니다.

「다른 워크스페이스가 사용 중인 설치입니다.」가 나오는 경우

설치 하나는 워크스페이스 하나에만 연결됩니다. 다른 워크스페이스에서 설치를 먼저 해제합니다(1-2).

「GitHub 설치가 비활성 상태입니다.」가 나오는 경우

설치가 해제되었거나 GitHub에서 권한이 회수된 상태입니다. 워크스페이스 관리자가 워크스페이스 설정 → 기타에서 다시 연결을 누르면 레포·이슈 연결이 그대로 복원됩니다.

계정을 연결했는데 기존 태스크의 담당자·작성자가 그대로인 경우

계정 연결은 이후 변경에만 적용됩니다. 프로젝트 관리자가 레포 줄에서 전체 가져오기를 실행하면 이미 가져온 태스크에도 다시 적용됩니다.

GDC에서 고친 내용이 GitHub에 반영되지 않는 경우

이슈 줄의 GDC 변경을 GitHub에 반영 스위치를 확인합니다. 가져온 이슈는 꺼진 상태로 시작합니다. 레포 동기화가 일시중지되지 않았는지도 확인합니다(2-4). 일정·진행률은 원래 반영되지 않습니다.

PR 목록에 「GitHub App에 Pull requests 읽기 권한이 없습니다.」가 나오는 경우

GitHub 앱에 Pull requests: Read-only 권한과 Pull request 이벤트 구독이 추가되고, 설치에서 재승인되어야 합니다. 앱을 관리하는 조직 관리자에게 요청합니다.
