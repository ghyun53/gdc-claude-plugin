자세히 보기

단계별로 어디서, 누가 하는지 정리. 1·3단계는 워크스페이스·프로젝트마다 1회, 2단계는 사람마다 1회 진행.

단계 위치 권한
1 워크스페이스에 GitHub 연결 워크스페이스 설정 → 기타 → GitHub 설치 연결 워크스페이스 소유자·관리자
2 내 GitHub 계정 연결 설정 → 연동 → GitHub 계정 연결 모든 사용자
3 프로젝트에 레포 연결 프로젝트 → 연동 → GitHub 레포 연동 프로젝트 관리자 (새 레포를 고를 때는 워크스페이스 소유자·관리자 권한도 필요)
4 이슈 발행·PR 연결 태스크 상세 → GitHub 영역 프로젝트 편집 권한이 있는 사용자 (뷰어 제외)

(참고) 연결 가능한 레포는 GDC GitHub 앱이 설치되고 접근이 허용된 레포뿐(현재 제머나이소프트 gemiso-dev 조직). 앱을 '선택한 레포'로 설치한 경우 해당 레포만 노출됨.

01

워크스페이스에 GitHub 연결

GDC 앱이 설치된 GitHub 계정·조직을 워크스페이스에 연결. 워크스페이스 소유자·관리자만 보이는 화면.

1 워크스페이스에 GitHub 연결 · 1-1 설치 연결하기

설치 연결하기

GitHub 로그인·승인 1회로 내 계정이 볼 수 있는 설치가 연결됨.

  1. 1

    왼쪽 위 워크스페이스 이름 → 워크스페이스 설정 → 기타 탭 이동

  2. 2

    GitHub 설치 연결 카드에서 설치 연결 클릭(이미 연결된 설치가 있으면 설치 추가)

  3. 3

    GitHub 화면에서 승인 → 기타 탭에 「GitHub 설치를 연결했습니다.」 표시되면 완료

  4. 4

    「연결할 수 있는 GitHub 설치가 없습니다.」 표시 = 앱 미설치 상태. GitHub에서 앱 설치 클릭해 설치(조직 설치는 그 조직의 Owner 권한 필요)

(참고) 이 승인으로 내 GitHub 계정 연결(2단계)도 함께 처리됨. 다른 계정으로 승인하면 GDC 연결 계정이 교체되고 카드에 안내 표시.

실제 화면
1 워크스페이스에 GitHub 연결 · 1-2 설치 관리

설치 관리

설치마다 계정·상태·레포 범위·연결된 레포 수·가져온 이슈 수 표시.

  1. 1

    설치 해제 클릭 시 이 설치를 쓰는 워크스페이스의 모든 프로젝트 연동 종료. 레포·이슈 연결은 보관되고 다시 연결 시 복원됨

  2. 2

    GitHub에서 앱도 제거하기 선택 시 레포 접근 권한까지 회수. 재사용하려면 앱 재설치 필요(조직 관리자 권한)

  3. 3

    설치 1개는 워크스페이스 1개에만 연결 가능. 옮기려면 기존 워크스페이스에서 먼저 해제

02

내 GitHub 계정 연결

내 GitHub 계정을 GDC에 연결해 두면 이슈 가져오기·발행 시 작성자·담당자로 인식됨. 사람마다 1회 진행.

2 내 GitHub 계정 연결

설정에서 연결

GitHub 로그인·승인 1회로 연결됨.

  1. 1

    사이드바 맨 아래(또는 오른쪽 위 프로필 메뉴)의 설정 → 연동 탭 이동

  2. 2

    GitHub 계정 연결 카드에서 GitHub 계정 연결 클릭 → GitHub에서 승인

  3. 3

    카드에 연결된 계정(@아이디) 표시됨. 해제를 원할 경우 연결 해제 클릭(이미 가져온 태스크는 유지)

(참고) 연결 전에 가져온 태스크는 프로젝트 관리자가 전체 가져오기(3-4)를 실행해야 작성자·담당자가 바뀜. 매칭 대상은 워크스페이스·프로젝트 멤버이고, 담당자 매칭은 프로젝트 멤버만 가능.

03

프로젝트에 레포 연결

프로젝트의 연동 탭에서 레포 연결. 이슈 관리·WBS 프로젝트 모두 가능. 프로젝트 1개에 레포 여러 개 연결 가능하고, 레포 1개는 프로젝트 1개에만 연결됨.

3 프로젝트에 레포 연결 · 3-1 레포 추가

레포 추가

워크스페이스에 연결된 설치에서 레포 선택.

  1. 1

    프로젝트의 연동 탭에서 GitHub 레포 연동 영역 확인

  2. 2

    레포 추가 클릭 → 레포 선택 → 다음 클릭(이미 연결된 레포는 「연결됨」으로 선택 불가)

  3. 3

    이어서 매핑 설정 창(3-2) 열림. 저장하면 연결 완료

(참고) 레포 목록은 워크스페이스 소유자·관리자만 조회 가능. 권한이 없으면 「레포를 찾을 수 없습니다.」로 표시되니 워크스페이스 관리자에게 요청. 새 프로젝트 생성 시 「GitHub 레포 연동」으로 대표 레포 1개 바로 연결 가능.

실제 화면
3 프로젝트에 레포 연결 · 3-2 매핑 설정

매핑 설정

레포의 사용자·라벨·상태를 GDC 항목과 연결. 기본값 확인 후 저장.

항목 내용 · 기본값
사용자 레포 이슈의 작성자·담당자. GitHub 계정 연결자(2단계)는 자동 매칭되고 나머지는 '미매핑'이 기본값. 비멤버는 작성자에만 매핑 가능.
라벨 라벨마다 태그·유형·우선순위·매핑 안 함 중 선택. type:…·priority:…는 프로젝트에 같은 값이 있으면 유형·우선순위로, 나머지는 태그로 연동됨. 없는 유형·우선순위는 이 창에서 생성 가능.
상태 열린 이슈·닫힌 이슈가 될 GDC 상태 지정. 기본값은 열림 = 예정 계열, 닫힘 = 완료 계열.
미매핑 담당자 매칭 실패한 담당자 처리 방식 선택 - 봇 계정에 귀속(기본값) 또는 비워둠. 매칭 실패한 작성자는 항상 봇 계정으로 귀속됨.

(참고) 프로젝트에 다른 레포가 있으면 사용자·상태 매핑을 함께 적용하는 옵션 제공(라벨 제외). 이 창을 열면 매칭된 워크스페이스 멤버가 프로젝트 멤버로 추가됨.

3 프로젝트에 레포 연결 · 3-3 기존 이슈 가져오기

기존 이슈 가져오기

매핑 저장 후 레포에 이미 있는 이슈 처리 방법 선택.

  1. 1

    전부 가져오기(기본값) 선택 시 이슈 전체가 태스크로 생성됨. 이슈가 많으면 시간이 걸리고 진행 상황은 레포 줄에 표시

  2. 2

    기존 이슈는 가져오지 않기 선택 시 연동 이후 생성·수정분만 유입됨. 나중에 전체 가져오기로 전량 수집 가능

  3. 3

    나중에 결정 선택 시 레포 줄에 범위 정하기 버튼 유지됨

(참고) 이후 GitHub 변경은 실시간 반영되고 레포 줄에 「실시간」 배지 표시. GitHub 하위 이슈는 GDC 하위 태스크로 유입됨.

3 프로젝트에 레포 연결 · 3-4 연결 관리

연결 관리

연결된 레포 줄에서 가능한 작업.

작업 설명
변경분 가져오기 마지막 가져오기 이후 변경분 수집.
전체 가져오기 (변경분 가져오기 옆 ▾) 레포 전체 재수집, 이미 가져온 이슈도 재동기화됨. 매핑 변경 후나 GitHub 계정을 새로 연결한 사람이 있을 때 사용.
매핑 설정 3-2의 매핑 설정 다시 열기.
동기화 일시중지 / 재개 (⋯ 메뉴) 중지 중에는 GitHub↔GDC 양방향 반영 없음(가져온 태스크는 유지). 재개 시 그동안의 GitHub 변경분 수집.
연동 해제 (⋯ 메뉴) 연동 종료. 가져온 태스크·연결된 PR은 유지되고, 가져온 태스크도 휴지통으로 보내기 선택 시 함께 이동됨. 해제한 레포는 「해제된 연결」에 보관 - 다시 연결 시 변경분까지 복원되고, 완전히 정리 시 태스크가 휴지통으로 이동되며 레포를 다른 프로젝트에 연결 가능.

04

태스크에서 사용하기

레포 연결 시 태스크 상세 패널 맨 위에 GitHub 영역 생성됨. 해당 태스크의 이슈·PR 표시.

4 태스크에서 사용하기 · 4-1 동기화 방향

동기화 방향

GitHub → GDC는 항상 반영, GDC → GitHub은 이슈별 스위치로 제어.

방향 반영되는 내용
GitHub → GDC 이슈 제목·본문·열림/닫힘·담당자·라벨·댓글이 실시간 반영됨. GitHub에서 이슈 삭제 시 태스크는 삭제가 아니라 숨김(보관) 처리.
GDC → GitHub 제목·설명·상태(열림/닫힘)·담당자·유형·우선순위·댓글 반영. 단, 이슈 줄의 GDC 변경을 GitHub에 반영 스위치가 켜진 경우만 적용되고 일정·진행률은 미반영.
실제 화면 · 가져온 이슈의 스위치(꺼짐)

(주의) 스위치 기본값이 다름. 가져온 이슈는 꺼짐, GDC에서 발행한 이슈는 켜짐 상태로 시작. GDC 수정이 GitHub에 안 보이면 이 스위치부터 확인.

4 태스크에서 사용하기 · 4-2 GitHub 이슈로 발행

GitHub 이슈로 발행

GDC 태스크를 GitHub 이슈로 발행. 태스크 1개에 이슈 1개 연결.

  1. 1

    태스크의 GitHub 영역에서 이슈 발행 클릭

  2. 2

    레포 선택(1개면 자동 선택). 일회성 복사가 아니면 발행 후에도 GDC 변경을 GitHub에 계속 반영합니다 유지

  3. 3

    발행 클릭 → 잠시 후 이슈 생성되고 이슈 맨 위에 GDC 태스크 링크 삽입됨

(참고) 태스크 생성 시 「GitHub 이슈로 발행」 선택 가능. 본문 이미지·첨부는 GDC 링크로 대체됨. 라벨은 레포에 같은 라벨이 있을 때만, 담당자는 GitHub 계정 연결 + 레포 권한이 있을 때만 반영.

실제 화면 · 태스크 생성 창
4 태스크에서 사용하기 · 4-3 PR 연결

PR 연결

태스크에 PR 직접 연결. 여러 개 연결 가능.

  1. 1

    태스크의 GitHub 영역에서 PR 연결 클릭

  2. 2

    최근 PR 목록에서 선택하거나 「목록에 없나요? 번호를 직접 입력하세요.」에 번호 입력

  3. 3

    연결된 PR은 상태(open·draft·merged·closed)와 함께 표시됨. 해제는 PR 줄에 마우스를 올려 연결 해제 클릭

(주의) PR 상태는 태스크 상태에 영향 없음. 병합되어도 태스크 상태는 직접 변경 필요.

4 태스크에서 사용하기 · 4-4 PR 자동 연결

PR 자동 연결

PR 제목·본문에 태스크를 적어 두면 자동 연결됨. 브랜치 이름은 미인식.

적는 방법 예시
GDC 태스크 링크 (키워드 불필요) https://gdc.gemiso.com/…/tasks/1234
키워드 + 이슈 참조 (같은 줄) 관련 이슈: #15 · Fixes #12, #13 · closes owner/repo#7

(참고) 키워드는 closes·fixes·resolves(과거형 포함), 관련 이슈·연관 이슈·관련 태스크·관련 작업. 참조 이슈가 같은 프로젝트의 태스크와 이미 연결되어 있어야 하고, 코드 블록·인용문 안의 텍스트는 무시됨.

(주의) 자동 연결 해제는 GDC가 아니라 PR에서 진행. PR 본문의 링크·참조를 지우면 연결도 해제됨. GDC에서만 해제하면 PR 수정 시 다시 연결됨.

05

자주 묻는 문제

막혔을 때 먼저 확인할 것.

레포 목록이 비어 있는 경우 (「레포를 찾을 수 없습니다.」)

새 레포 선택에는 워크스페이스 소유자·관리자 권한 필요(프로젝트 관리자도 동일). 워크스페이스 관리자에게 요청.

관리자인데도 안 보이면 GitHub 앱에 그 레포 접근이 허용되지 않은 상태. GitHub에서 앱의 레포 접근 범위 확인.

「'…' 프로젝트와 연동된 레포입니다.」가 나오는 경우

레포 1개는 프로젝트 1개에만 연결 가능. 기존 프로젝트에서 연동 해제 후 완전히 정리(3-4) 먼저 실행.

「다른 워크스페이스가 사용 중인 설치입니다.」가 나오는 경우

설치 1개는 워크스페이스 1개에만 연결 가능. 다른 워크스페이스에서 먼저 해제(1-2).

「GitHub 설치가 비활성 상태입니다.」가 나오는 경우

설치가 해제되었거나 GitHub에서 권한이 회수된 상태. 워크스페이스 관리자가 워크스페이스 설정 → 기타에서 다시 연결 클릭 시 레포·이슈 연결 복원됨.

계정을 연결했는데 기존 태스크의 담당자·작성자가 그대로인 경우

계정 연결은 이후 변경에만 적용됨. 프로젝트 관리자가 레포 줄에서 전체 가져오기 실행 시 기존 태스크에도 재적용.

GDC에서 고친 내용이 GitHub에 반영되지 않는 경우

이슈 줄의 GDC 변경을 GitHub에 반영 스위치 확인(가져온 이슈는 꺼짐). 레포 동기화 일시중지 여부도 확인(3-4). 일정·진행률은 원래 미반영.

PR 목록에 「GitHub App에 Pull requests 읽기 권한이 없습니다.」가 나오는 경우

GitHub 앱에 Pull requests: Read-only 권한과 Pull request 이벤트 구독 추가 후 설치 재승인 필요. 앱을 관리하는 조직 관리자에게 요청.
